# 候选判据规格：八类判据的 params 与静态校验规则

判据是**纯函数**：同输入同输出，不依赖时钟、随机数、网络、模型。
一条判据 = `{clause_id, title, kind, params, standard}`，`kind` 决定 `params` 的必填键。

## 一、总表

| `kind` | 判定语义 | 必填 `params` | 校验规则 |
|---|---|---|---|
| `格式约束` | 字段必须匹配正则 | `field`, `pattern` | `pattern` 必须能被 `re.fullmatch` 编译；`field` 必须是非空字符串 |
| `受控词表` | 取值必须属于枚举（白名单） | `field`, `allowed` | `allowed` 必须是非空数组；元素为字符串 |
| `必填约束` | 字段存在且非空 | `field` | `field` 非空；空字符串与空数组都算未填 |
| `条件必填` | 条件成立时某字段必须有值 | `when_field`, `when_value`, `require_field` | 三个键都非空；`when_field != require_field` |
| `数值范围` | 数值落在区间内 | `field`，且 `min`/`max` 至少一个 | `min`、`max` 为数值；同时给出时 `min <= max` |
| `跨字段一致性` | 两字段的序关系 | `left`, `right`, `op` | `op ∈ {<=, >=, <, >, ==}`；`left != right` |
| `跨文档引用` | 取值必须存在于受控清单（白名单） | `field`, `registry` | `registry` 必须在已声明清单里 |
| `禁止取值` | 取值不得属于受控集合（黑名单） | `field`, `registry` | 同上；`registry` 指向「禁用集合」而不是「允许集合」 |

> `跨文档引用` 与 `禁止取值` 的 `registry` 语义相反，**用错方向会造成系统性误判**：
> 白名单用错 → 合规数据被误判违规；黑名单用错 → 违规数据被放行。
> 提案时必须在 `rationale` 里写明你用的是哪一个方向。

## 二、四类「缺字段」行为（写提案时必须知道）

| 类型 | 字段缺失时的行为 |
|---|---|
| `格式约束` / `受控词表` / `数值范围` / `跨文档引用` / `禁止取值` | **放行**（缺字段由 `必填约束` 负责，不重复报） |
| `必填约束` | 报违例 |
| `条件必填` | 条件不成立→放行；成立但目标缺失→报违例 |
| `跨字段一致性` | 任一字段缺失或为 `None`→放行 |

推论：**不要指望一条 `受控词表` 判据去抓「字段没填」**。要抓缺失就同时提一条 `必填约束`。

## 三、什么时候必须提「判据语言扩张」

出现下面任一情形，说明八类判据表达不了这条规则，**不要换一个近似类型硬塞**：

1. 规则要求「取值**不得**在某个集合内」，而现有类型只有白名单语义 → 需要黑名单类型。
2. 规则涉及**三个及以上字段**的联合约束（现有 `跨字段一致性` 只支持两字段一个算子）。
3. 规则的对象不是「一条资产的字段」，而是**资产之间的关系或图结构**（例如两条资产不能同时占用同一资源）。
4. 规则要求**跨文档的聚合**（例如「同一批次内哈希不得重复」）。

处理方式：把候选项标为 `kind: "__grammar_extension__"` 并在 `rationale` 里写清
「现有类型为什么表达不了 + 期望新增的判定语义」，提交给裁决。
**这是合法且被鼓励的提案**——历史上黑名单类型正是被一次失败逼出来的，不是设计时想到的。

## 四、`clause_id` 与不重复

- 新判据的 `clause_id` 必须是**当前判据库中不存在的编号**。先用 `std_clause_list` 取回全部编号，取最大号 +1，或按条号插入规则（如 `第10条之一`）。
- **不重复判据**：同 `kind` + 同约束目标（`field`，或 `left/right`，或 `when_field/require_field`）视为同一约束面。若已有等价判据，提案会被否决——先检查再提。
- 修正已有判据时，提**修订提案**（同一个 `clause_id` + 说明修订理由），不要新建一条与旧判据冲突的规则并存。

## 五、参数取值从哪来（禁止拍脑袋）

| 参数 | 唯一合法来源 |
|---|---|
| `allowed`（受控词表） | `std_hard_anchors` 返回的锚点样本，或标准附录/码表原文 |
| `min` / `max`（数值范围） | 条款原文里写明的界，或锚点样本的观测边界 |
| `pattern`（格式） | 条款原文的格式描述，转成可编译正则；**必须实测能被通过样本匹配** |
| `registry`（受控清单） | `std_clause_list` 里已声明的清单名 |
| `when_value`（条件触发值） | 必须是该字段受控词表里的一个合法取值 |

规则：**任何参数都要能指向一条锚点或一句条款原文。** 指向不了的参数就是猜的，会被判证据不足。

## 六、提案 JSON 的最小形态

```json
{
  "clause_id": "第17条",
  "title": "资产标识不得指向已注销条目",
  "kind": "禁止取值",
  "params": {"field": "asset_id", "registry": "retired_assets"},
  "standard": "工业数据资产登记与校验规范（演示样例）",
  "blindspot_ids": ["BS-001"],
  "anchor_ids": ["AN-007"],
  "compliant_samples": ["AST-2026-0007"],
  "rationale": "白名单判据只能表达『取值必须在清单内』；本盲区要求『取值不得在已注销集合内』，方向相反，必须用黑名单类型。锚点 AN-007 给出 retired_assets 的 3 个条目；AST-2026-0007 是同类合规样本，用于证明不误伤。",
  "expected_effect": "对 BS-001 的 2 条样本产生 2 条违例；对现有 5 条合规样本产生 0 条违例"
}
```

`rationale` 与 `expected_effect` 不是装饰：裁决要用它们判断这条判据是不是在拟合样本。
**`expected_effect` 必须能在提案后用 `std_verify` 复算。**
