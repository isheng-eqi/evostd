# 22 · 方向再迭代：自进化的天花板在"什么算对"

> 本文推翻并升级了 `docs/21` 的方向。21 版没有错，但**只对了一半**。
> 结论先行：**自进化不是"系统能改自己"，而是"系统能扩大它分辨对错的范围"。**
> 真正的深水区不是让智能体变得更强，而是**让"什么算对"本身能够长大**。

---

## 一、先把"自进化是什么"问到见底

三个逐层加深的答案。前两个是流行理解，第三个是我认为正确的。

### 答案一（流行）：自进化 = 系统能改自己
**不够。** 一个系统能改自己的代码，但改的方向由人给的固定评分决定——那只是自动优化，不是自进化。

### 答案二（较准）：自进化 = 改进算子本身也在被改进的集合里
$$\theta_{t+1} = U_\phi(\theta_t, E_t), \quad U \in \theta$$
**更准，但仍不够。** 它只说了"能改 U"，没说"改成什么算好"由谁定。如果"算好"始终由同一把尺子定义，那么无论 U 怎么改，天花板从一开始就钉死了。

### 答案三（本文主张）：自进化 = 系统扩大"它能够分辨的对错"的范围

依据是一条硬结论——**平稳性二分**（arXiv:2609.34924）：

> 迭代式自我修改，**只要可达编辑集保持不变，就必然落入严格递减收益**；
> 唯一逃脱的方式是**让这个集合扩大**。

而"可达编辑集"里最关键的一项，**不是"能改哪些文件"，而是"它能辨识的对错的范围"**。
一个系统可以改一千个参数，但如果它判断对错的标准始终是那 12 条判据，它一定会撞墙。

> ## 所以：自进化的真正度量不是"改了多少"，而是"辨别力的边界扩张了多少"。

**两重实证支撑**：

| 方向 | 证据 |
|---|---|
| 正面：能自举的系统，辨别力都来自**外部** | AlphaEvolve / FunSearch 强制要求用户提供 `evaluate` 函数；Absolute Zero 靠代码执行器；DGM/HGM 靠 SWE-bench 通过率 |
| 反面：把验证器换成模型自己，辨别力**不增长只会漂移** | Self-Refine / Self-Rewarding：迭代 10 轮后自评偏见 8.06→**14.6**，而人类评分显示质量**没有可测量的提升**——它只是自认为在提升 |

---

## 二、用这把尺子量我上一版方向：它对，但只对了一半

**上一版（docs/21）**：标准 → 编译成判据 → 智能体在判据上自进化（本体 / Skill 模板 / 检索策略）。

用"辨别力边界"这把尺子量它：

| 量什么 | 结论 |
|---|---|
| 判据库 | **固定**——由我（人）从标准编译出来，12 条，之后不再变 |
| 系统能分辨的对错 | **从一开始就被钉死了** |
| 它实际在做什么 | **在固定靶子上打得更准**，不是"能看见更多靶子" |
| 按平稳性二分 | **必然撞天花板** |

**所以上一版是一阶自进化。** 它有价值（是必要的地基），但它不是深水区。

> **深水区是二阶：让"什么算对"本身能够长大。**

---

## 三、二阶自进化：验证器自己长大，但裁决权锁在它够不着的地方

这是整个方向的核心。讲清三件事：**谁能长大 / 谁裁决 / 人的角色**。

```
┌──────────────────────────────────────────────────────────────────────┐
│ L2  认知产物（在判据库上被裁决）                                       │
│     本体 · 抽取规则 · 资产标识规则 · Skill 工作流模板 · 检索-推理策略   │
│     ← 上一版做的就是这个，仍然保留，但它现在是"二阶的下游"             │
├──────────────────────────────────────────────────────────────────────┤
│ L1  ★ 判据库（自进化的主对象）                                         │
│     · 从标准编译得到的种子判据（12 条）                                 │
│     · **系统自己提案的新判据**（发现盲区 → 提出约束 → 被裁决 → 入库）    │
│     · 判据库长大 ⟹ 系统能看见以前看不见的对错                          │
├──────────────────────────────────────────────────────────────────────┤
│ L0  ★ 锚点（唯一不可进化的东西 = 系统的外部真值）                       │
│     人工确认过的**极少量**违例样本与合规样本 + 标准原文条款               │
│     · anchor-dev：系统提案时可见（用于自我筛选）                        │
│     · anchor-test：只在审计时读（测真实辨别力，防过拟合锚点）            │
└──────────────────────────────────────────────────────────────────────┘
```

### ★ 核心设计：系统的自由度在"提案"，不在"裁决"

这一条是整个方向的安全阀，也是"谁验证验证器"的**工程答案**：

> **验证器不能自证，只能被独立锚点集证伪。**
> 系统可以自由地**提出**新判据；但"这条判据对不对"永远由锚点集裁决，而锚点集**物理上不在系统的编辑范围内**。

对照实证（arXiv:2610.11464）：自进化验证器**去掉 anchor 守卫后会塌缩成"永远通过"的空壳判官，却照样能训出好技能**——
也就是说**下游分数根本无法认证验证器**。既然下游认证不了，那就只能靠**独立锚点**。这不是可选项，是唯一出路。

### 人的角色被降级了——这正是"低资源"的真实含义

| | 传统做法 | 本方向 |
|---|---|---|
| 人要做什么 | **写规则**（把标准翻译成判据） | **确认极少量样本**（这条是不是违规：是/否） |
| 人的工作量 | 与标准规模成正比 | 与**盲区数量**成正比，通常个位数到几十 |
| 系统负责 | 执行规则 | **发现盲区 + 提出规则 + 在锚点上自证** |

> **低资源 ≠ 数据少。低资源 = 不需要人写规则，只需要人点头。**

这句话直接回应赛题的"低资源场景下领域知识图谱本体半自动化构建"——
但它的层次比"半自动构建本体"高一阶：**连"什么算对"都不需要人写，只需要人确认。**

## 四、为什么这是 2026 年的正确位置（不是自我感觉良好）

| 判据 | 证据 |
|---|---|
| **它是公认瓶颈** | 2026 年至少三篇独立工作把瓶颈指向验证器；`Who Verifies the Verifier?` 直接把问题写进标题 |
| **它有反直觉的硬结论** | 去掉 anchor 守卫 → 验证器塌缩成"永远通过"的空壳判官，**下游分数却看不出异常** |
| **它无人占位** | 我在 2026 前沿扫描里排出的"最值得占据的位置"，第 1 名就是这个；相关尝试（Red Queen Gödel Machine 等）仍自认"是逃离循环还是搬移循环，未决" |
| **它有安全边界** | 人保留锚点 = 保留否决权。系统越活跃，越不能碰锚点 |
| **它可度量** | 判据库在 **anchor-test** 上的辨别力（F1/AUC）随代数变化——**这是一条二阶曲线，不是一阶的分数曲线** |

## 五、可证伪的设计：怎么知道它成了，怎么知道它是假的

### 成功的样子
一条**二阶曲线**：判据库规模 ↑ 的同时，**在 anchor-test 上的辨别力 ↑**。
含义：系统不但打得更准，而且**看见了以前看不见的违规**——它能分辨的对错的范围真的变大了。

### 造假的样子（必须主动设防）
| 造假形态 | 检测手段 |
|---|---|
| 判据库靠"堆条数"涨分 | 同时报**精度**：新判据在合规样本上的**误报率**必须为 0 或极低 |
| 过拟合 anchor-dev | **anchor-test 与 dev 的落差**（同"代理-真实落差"）：落差 > 阈值 → 判定造假 |
| 提了一条"永远通过"的空壳判据 | **对抗探针**：恒真判据必须被裁决拒收；恒假判据同理 |
| 新判据只是旧判据的换皮 | **区分度检查**：新判据必须能区分出至少 N 条旧判据全部放行的样本 |
| 判据自己漂移 | 记录每条判据的**历史命中率**，命中率单调上升 = 它在"适应数据"而不是"发现规则" |

### 最小可证伪实验（我可以立刻跑）
1. 造一批资产，其中**一部分违规是现有 12 条判据全部测不到的**（盲区）
2. 给出**极少量**锚点（人工确认）
3. 让二阶回路跑：发现盲区 → 提案判据 → 在 anchor-dev 上裁决 → 入库
4. 度量：判据库在 **anchor-test** 上的 F1 随代数变化

**若 F1 不涨 → 方向证伪，立刻回头。** 这比再写一万行代码有价值。

## 六、与赛题的关系：它是实例，不是约束

赛题三仍然完整满足，但**每一条都落在"因为要自进化所以必须要它"的位置上**：

| 赛题要求 | 在二阶框架里的位置 |
|---|---|
| 多模态异构数据 | L2 的输入层 |
| **标准 / 规范体系** | ★ **L1 判据的来源**（种子判据）与 **L0 锚点的文本依据** |
| 本体半自动构建 + 持续更新 | L2 的进化对象之一 |
| 检索-推理双驱动 | L2 的进化对象之一 |
| Skill 工作流模板沉淀 | L2 的进化对象之一 |
| **决策链路可溯源** | ★ **L0 锚点与判据裁决的审计底座**——没有溯源，锚点就不可信 |
| 基于 Nexent 可运行 | L0/L1 **必须放在 agent 够不着的地方**（MCP 工具内）——平台边界就是安全边界 |

**注意最后一行**：如果锚点和判据库都放在 agent 够得着的地方，"裁决权不可被系统触碰"就成了一句空话。
**赛题的"基于 Nexent 可运行"要求，恰好给了我们一个天然的隔离边界。**

## 七、一句话

> **别人在优化答案；我们在让"判对错的能力"自己长大——而最终裁决权，锁在 agent 够不着的地方。**
