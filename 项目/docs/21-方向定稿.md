# 21 · 方向定稿：标准驱动的自进化引擎

> 本文是方向收敛的结论。**一切以自进化为准，赛题要求只作为第一个实例，不作为约束。**

---

## 一、把赛题读成"环境"，而不是"规格"

赛题三表面上要求六件事（多模态识别、资产标识、本体半自动构建、持续更新、标准对齐、MCP/Skills 双驱动、多跳溯源、Skill 沉淀）。
但如果把它读成**一个自进化系统的运行环境**，它的每一件要求都落在回路的某个位置上——**不是约束，是必需件**：

| 赛题要求 | 在自进化框架里它是什么 | 为什么"必须要它" |
|---|---|---|
| 多模态异构数据 | **进化的输入层** | 没有输入就没有变异素材 |
| **行业标准 / 规范体系** | ★ **验证器的来源** | **没有它就没有目标函数，回路无从谈起** |
| 本体半自动构建 + 持续更新 | **进化对象 L1** | 本体是智能体"知识边界"的表示 |
| 检索-推理双驱动 | **进化对象 L3** | 编排策略决定每次行动的质量 |
| 沉淀可复用 Skill 模板 | **进化对象 L2** | 模板是"经验"的可复用形态 |
| 跨文档多跳 + 决策链路可溯源 | ★ **审计底座** | **没有溯源就无法判断"是不是自欺"** |
| 基于 Nexent 可运行 | **落地形态** | 验证器要放在 agent 够不着的地方 |

**最珍贵的两件东西是"标准"和"溯源"**——
标准给了我们**外部验证器**（这是自进化的燃料），
溯源给了我们**审计底座**（这是防止自欺的骨架）。

> **所以正确的方向不是"做一个数据资产认知智能体"，而是：**
> ## **把权威标准编译成可执行的对错判据，让智能体在这个判据上自己长本事；长出来的每一样东西（本体、标识规则、抽取规则、Skill 模板、编排策略）都必须能追溯到标准条款。**

## 二、方向陈述（定稿）

### 一句话

> **造一个"标准驱动、可自证"的自进化引擎，并把它实例化为行业数据资产认知智能体。**

### 三个部件

```
┌─────────────────────────────────────────────────────────────────┐
│ ①  标准编译器  Standard → Verifier                               │
│    把条款编译成可执行的检查器：条款 → 判据 → (通过/不通过 + 证据 + 条款引用) │
│    ★ 这是整个系统的"目标函数工厂"，也是最大差异化                    │
├─────────────────────────────────────────────────────────────────┤
│ ②  自进化内核  Evolution Core（已完成）                            │
│    候选 / 外部验证器 / 对照闸门 / 岛屿存档 / 审计 / 台账 / 主循环      │
├─────────────────────────────────────────────────────────────────┤
│ ③  三条进化线 + 一个元机制                                         │
│    L1 本体（含抽取规则）  L2 Skill 模板  L3 检索-推理策略             │
│    ★ 元机制：平台期自动"扩张可达编辑集"——从标准里发现还没被覆盖的约束类型 │
└─────────────────────────────────────────────────────────────────┘
```

### 差异点（一句话）

> **别人做的是"接了大模型的文档问答"；我们做的是"一个把标准当靶子、自己练、并且能证明自己没作弊的智能体"。**

## 三、为什么这个方向是"正确"的——五条实证支撑

每条都来自调研，不是感觉：

| # | 设计选择 | 实证依据 |
|---|---|---|
| 1 | **验证器来自外部标准，绝不用模型自评** | 把验证器换成模型自己的系统（Self-Refine / Self-Rewarding）是后来被打得最狠的：迭代 10 轮后自评偏见从 8.06 涨到 14.6，而人类评分显示**质量没有可测量提升** |
| 2 | **验证器放在 MCP 工具里，agent 够不着** | 模型自认"被评测"时作弊率 6.5%、自认"真实部署"时 **55.1%**；提示词约束只能降低不能消除 → 护栏必须结构性 |
| 3 | **平台期要主动"扩张可达编辑集"** | 平稳性二分（arXiv:2609.34924）：可达编辑集固定 ⟹ **严格递减收益**，唯一逃脱是让集合扩大。原话："审计脚手架，而不是检查点" |
| 4 | **先爬山再加机制** | Hill Sampling（arXiv:2609.25510）：反复对当前最优解采样编辑即可超过 AlphaEvolve；而 **测试时用 ES 训权重不如把学习率设成 0** |
| 5 | **审计常驻 + 保留集落差** | GPU kernel 优化里 **73.8%** 出现"代理涨、真实没涨"，且**跑得越久越严重**（10 步 26.4% → 100 步 57.8%） |

## 四、三条进化线 + 元机制（具体定义）

### L1 本体自进化（含元层）
- **进化对象**：概念集 / 关系 / **抽取规则本身**
- **验证器**：① 语料侧术语覆盖率（外部，不依赖本体）② 标准对齐检查（编译自标准）③ 内部一致性
- **变异**：从"未被覆盖的高频术语"提候选；从"抽取失败样本"改抽取规则
- **元层**：抽取规则是候选的一部分 → 系统在改"怎么建本体"

### L2 Skill 模板自进化
- **进化对象**：工作流模板库（何时用 + 步骤序列）
- **验证器**：held-out 任务集上的解决率 − 冗余步数惩罚 − 无用模板惩罚
- **变异**：**从失败诊断提炼模板**；泛化/特化；剪枝
- **目标形态**："够通用但不臃肿"的一小组模板

### L3 检索-推理策略自进化
- **进化对象**：双驱动的编排序列（先推理定位条款还是先向量检索；何时回检原文；何时拒答）
- **验证器**：决策正确率 + **溯源完整率**（每个结论是否挂得上条款）+ 步数成本
- **变异**：交换/插入/删除编排步；改触发条件

### ★ 元机制：平台期扩张可达编辑集
当三条线都停滞时，系统**从标准文本里发现"还没被覆盖的约束类型"**，生成新的约束模板
（例如从"字段级约束"扩张到"跨文档一致性约束"），从而**抬高天花板本身**。
这是把纪律 3 变成可执行机制——也是最容易被忽略、最能体现深度的设计。

## 五、执行顺序（现在开始）

| 阶段 | 做什么 | 状态 |
|---|---|---|
| P0 | 自进化内核 + 对照闸门 + 审计 | ✅ 已完成（两条线实测 1.0000 / 0.9790，落差 0 / +0.0023，探针 1.0） |
| **P1** | **标准编译器**：条款 → 可执行检查器 → 违例报"违反第 N 条" | ⏳ **现在做** |
| P2 | 挂上 Nexent：把内核与编译器做成 MCP 工具 + Skill | ⏳ |
| P3 | 三条进化线接真实语料与真标准 | ⏳ |
| P4 | 初赛交付（文档 + 截图 + JSON + 说明） | ⏳ |

**行业只需在 P3 之前定。** P1、P2 完全不依赖它——这正是"内核先行"的意义。

## 六、一句话总结

> 我们造的是一把**能自己校准的枪**——而且它每次校准都留痕，可以被任何人当场验算。
