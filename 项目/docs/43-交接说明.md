## 五、本项目的核心概念（读代码前先读这个）

**自进化 = 系统扩大「它能够分辨的对错」的范围。**

- **判据语言 12 类**：数值范围 / 受控词表 / 格式约束 / 必填约束 / 条件必填 /
  跨字段一致性 / 跨文档引用 / 禁止取值 / **基准时间约束 / 查表区间 /
  集合级唯一性 / 条件禁止**（后 4 类是被实测盲区逼出来的）

- **十条防自欺机制**：锚点自检 · 弃权清单 · 盲区成因分型 · 判据冲突检测 ·
  准入裁决 · 降级台账 · 能力对账 · 重启一致性 · 判据跳过可见 · 转发器心跳

**一句话**：让"看起来正常"和"真的正常"无法混淆。

## 七、几条踩过的坑（避免重踩）

| 坑 | 教训 |
|---|---|
| 按**行号**批量替换代码 | 行号会随前一次改动漂移。**按内容唯一匹配改，改完立刻 `ast.parse`** |
| 只测一个领域 | 有一次改坏 `asset_list`，两个领域都返回 0 条 —— 只测一个会发现不了 |
| grep 一种写法就以为查全了 | `domains.manufacturing` 查过之后，裸字符串 `"manufacturing"` 还有 7 处 |
| 假定某列唯一 | `ag_tool_instance_t` 的 `tool_instance_id` **不是唯一键**，导致去重 SQL 恒为假 |
| 空集合上的指标 | 空评测集上 `best_score = 1.0` —— **假满分**，不是好结果 |
| 报告里写"已修" | 有一次写了"已修"而**代码里没改**。**唯一能确认的是 grep 与实跑，不是记忆** |
| "保守方向的静默" | `except: continue` 跳过一条判据 → 那条资产少判一条，而输出上"少判"和"判过且合规"长得一样 |

## 九、★ 八种「存在但未验证」与各自的检查（本区间新增）

这个项目反复出现同一类问题：**某样东西"在"，但没人验证过它真的在工作。**
下面八种形态**各有一个可复跑的检查脚本** —— 它们不是一次性验证。

| # | 形态 | 检查脚本 | 期望结果 |
|---|---|---|---|
| 1 | 判据"存在" ≠ "能触发" | `tools/clause_liveness.py` | 两领域均 **100%** |
| 2 | 技能"绑上了" ≠ "能跑" | 静态校验（结构 + 工具引用） | 5/5 · 引用 17/17 存在 |
| 3 | 快照"有接口" ≠ "能退回" | `tools/snapshot_roundtrip.py` | 两领域「往返完全一致」 |
| 4 | 工具"注册了" ≠ "被跑过" | `tools/tool_liveness.py` | **0** 个未被引用 |
| 5 | 工具"能跑" ≠ "调用形式对" | `tools/smoke_all_tools.py` | **33/33** `ok=True` |
| 6 | 缓存"加了" ≠ "会失效" | 手工实测（见 docs/42 第 153 节） | 改库后耗时回升 |
| 7 | 工具存在 ≠ 智能体知道 | `skills/README.md` 的程序生成索引 | **36/36** 覆盖 |
| 8 | 说明文字是否**真的是**说明 | `tools/fake_docstring.py` | **0** 处 |
| 9 | **标准体系是否真的对齐过** | `tools/cross_standard.py` | 两张标准共享字段 **8** 个：一致 3 / A 更严 1 / B 更严 3 / 冲突 1 |

### 共同判据

> **凡是"A 声称 B"的地方，都要有一个能把"声称"与"实际"对上的动作。**
>
> **"声称"是免费的；"对上"需要一次主动的动作。**
> 这八种全都是**"没人去对，它就一直错着"** —— 而且它们**都不影响功能测试**。

### 相关的坑（都踩过，写在这里省得重踩）

| 坑 | 表现 |
|---|---|
| `import evostd.server` 早于设 `EVOSTD_STATE` | 脚本**静默读另一个库**（`shadow_map.py` / `clause_liveness.py` 都中过） |
| 检查器把"**提及**"当"**引用**" | 脚本在 docstring 里列一遍工具名，就把自己的发现抹掉了 |
| 检查器只认直接调用 `foo(` | **看不见**用 `call("foo", ...)` 字符串派发写的冒烟脚本 |
| 测试**读错键路径** | 追了三轮不存在的 bug（真因是 `g['lv']['k']` 写成了 `g['k']`） |
| `dict.get()` 取不到键 | **把"键不存在"和"值为空"混为一谈** —— 后者是事实，前者是 bug |
| `| tail -N` 过滤输出 | 让"失败"和"没输出"长得一样（错误被过滤掉了） |

### 一句总结

**这个项目的真正产出，不是那 36 个工具，而是这八个"对账动作"。**
工具回答"能做什么"；**对账动作回答"它是不是真的在做"。**
