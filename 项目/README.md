# 项目：标准驱动的自进化引擎

> **方向定稿（见 [`docs/21-方向定稿.md`](docs/21-方向定稿.md)）**：
> 把权威标准编译成可执行的对错判据，让智能体在这个判据上自己长本事；
> 长出来的每一样东西（本体、标识规则、抽取规则、Skill 模板、编排策略）都必须能追溯到标准条款。
>
> 定位：**与行业解耦**。行业只提供 Domain Pack（语料 + 标准 + 叙事），内核与编译器一行不改。
> 现状：内核已跑通并自检通过；标准编译器已跑通；**行业尚未锁定**（见 `docs/10`）。

### 一句话差异点

> 别人做的是"接了大模型的文档问答"；我们做的是**"一个把标准当靶子、自己练、并且能证明自己没作弊的智能体"**。

| 部件 | 作用 | 状态 |
|---|---|---|
| **标准编译器** `src/standard/` | 条款 → 可执行判据（7 类）→ 违例报"违反第 N 条" | ✅ 已跑通 |
| **自进化内核** `src/evolve/` | 候选/外部验证器/对照闸门/岛屿存档/审计/台账/主循环 | ✅ 已跑通 |

## 一、为什么先做内核，而不是先选行业

一句话：**自进化与行业的关系，是优化算法与目标函数的关系**——行业不提供算法，行业只提供**目标函数（验证器）**。
所以"能不能做自进化"取决于三件事，而这**四类候选行业全都满足**：

1. 结果可判定（有权威文本规定"什么是对的"）→ 制造/金融/政务/医疗 都满足
2. 验证成本低（秒级、确定性）→ 都满足
3. 可 held-out → 都满足

行业真正影响的是另外三件事：演示效果、多模态数据可得性、业务故事强度——**这些决定分数，不决定回路能不能跑**。
详见 [`docs/10-自进化与行业的关系-DomainPack架构.md`](docs/10-自进化与行业的关系-DomainPack架构.md)。

**因此决策顺序是：先证明内核能跑出真曲线 → 再按分数排序挑行业。**

## 二、内核结构（`src/evolve/`）

```
src/evolve/
  core.py                自进化内核：候选 / 验证器协议 / 对照闸门 / 存档 / 审计 / 台账 / 主循环
  verifiers.py           验证器的实现（★ 唯一被行业实现的地方）
  domains/
    ontology_growth.py   领域包 L1：本体生长（合成语料，无任何模型参与打分）
    skill_templates.py   领域包 L2：Skill 工作流模板进化
  run_demo.py            端到端演示 + 自检报告
  runs/                  每次运行的 report.json / gate.json / ledger.jsonl

src/standard/
  compiler.py            标准编译器：Clause/Finding/Checker + 7 类判据 + StandardVerifier
  samples.py             演示样例标准（14 条，含 2 条故意不可编译的）
  demo.py                编译器演示：合规/违规资产 → 违例回指条款
```

### 六条设计纪律（全部写进代码，不靠自觉）

| # | 纪律 | 代码位置 |
|---|---|---|
| 1 | **先爬山，再加机制**：父代 80% 取当前最优，20% 按 CMP 采样保留探索 | `Archive.sample_parent(hill_ratio=0.8)` |
| 2 | **验证器必须外部**：分数只由确定性程序给出，LLM 不得参与打分 | `Verifier` 协议 + `RuleSetVerifier` |
| 3 | **对照闸门**：用"施加/扣住"配对消融裁决去留，不看绝对分 | `ContrastRecord.judge()` |
| 4 | **存档留踏脚石**：保留劣质祖先，用后代表现（CMP）估改进潜力 | `Archive.cmp()` |
| 5 | **审计常驻**：对抗探针 + 代理-真实落差 + 塌缩检测 | `Auditor` |
| 6 | **一切可回滚**：追加式台账 | `Ledger` |

### 一处关键的工程细节：闸门阈值随验证器性质自适应

```python
min_n = 1 if verifier.deterministic else 3     # 确定性验证器 + 配对消融 = 单次即精确结论
consecutive = 1 if verifier.deterministic else 2
```
**理由**：`min_n=3` 是为了对抗**采样噪声**。若验证器是确定性的（同输入同输出）且用配对消融，就不存在采样噪声，单次测量即精确结论。用 3 反而会让闸门永远停在 `insufficient`——**这是第一次跑的时候真实发生的 bug**。

### ⑤ 第二个 Domain Pack：Skill 工作流模板进化（对应赛题要求④）

**内核一行没改**，只换了一个领域包。这个领域把"沉淀模板"变成有拉扯的优化问题：

| 目标 | 惩罚 |
|---|---|
| 模板太窄 → 任务解不了 | solve_rate 低 |
| 模板太肥（一个大而全的模板） | 每多一步无用步骤罚 0.03 |
| 模板太散 | 每个用不上的模板罚 0.01 |

进化信号来自**真实失败诊断**（哪个任务失败、缺哪一步），不是模型自评。

| 代数 | 0 | 1 | 3 | 5 | **10** |
|---|---|---|---|---|---|
| score | 0.0000 | 0.3273 | 0.4773 | 0.8047 | **0.9790** |

进化出的模板库（**只有 3 个模板，solve_rate = 1.0**）：

```
[合规校验] 检索条款 → 生成结论 → 抽取字段 → 校验一致性 → 引用溯源
[数值核算] 抽取字段 → 计算指标 → 生成结论 → 检索条款 → 校验一致性
[证据溯源] 检索条款 → 引用溯源 → 生成结论 → 抽取字段
```

- 保留集 0.9767 / 代理-真实落差 **+0.0023** ✅
- 探针通过率 **1.0**——注意 `all-in-one`（一个万能模板干所有事）拿到 0.9390，**被正确排在 0.9790 之后，margin 只有 +0.04**。这个 margin 小得很诚实：万能模板确实也能全解，它只是**臃肿**，而"精简"正是这条进化线要学的东西。

## 三·五、标准编译器实测（`python -m standard.demo`）

把权威文本变成自进化的靶子。演示样例标准 14 条 → **编译成功 12 条（86%）**，判据类型覆盖 7 类：

`格式约束 ×2`、`受控词表 ×2`、`必填约束 ×2`、`条件必填 ×2`、`跨字段一致性 ×1`、`数值范围 ×2`、`跨文档引用 ×1`

**每一条违例都回指条款并附原文**（这是"对齐有牙齿"+"决策可溯源"的同一个落点）：

```
✗ 违反《工业数据资产登记与校验规范（演示样例）》第9条：
   当 secrecy=「秘密」时，declassify_date 必须填写
   原文：「密级为“秘密”的数据资产，应同时登记解密日期。」
   证据：{'field': 'declassify_date', 'when': 'secrecy=秘密'}

✗ 违反 第11条：不一致：要求 collect_time <= ingest_time，
   实际 collect_time=「2026-04-01」 ingest_time=「2026-03-05」
   原文：「数据资产的采集时间不得晚于入库时间。」

✗ 违反 第15条：cited_standards 引用了受控清单外的条目：['GB/T 99999-2099']
   原文：「数据资产引用的标准编号，应存在于受控标准清单中。」
```

**★ 编译器必须承认自己编译不了什么**：2 条"只能靠人判断"的条款（业务真实性、描述清晰度）被
**明文列出而非偷偷丢掉**——它们是**下一步扩张可达编辑集的入口**（见 `docs/21` 元机制）。

**合规率 = 可以直接拿去做自进化的适应度**：外部、确定性、可回指条款。它不是模型给的分数，是标准给的裁决。

## 四、★ 第一次运行抓到的两个真 bug（这是审计机制的价值实证）

第一次跑出来的曲线**很难看**：卡在 F1=0.6667，而且**"全选"这个坏候选拿了同样的 0.6667**。
审计模块当场报警（探针通过率 0.0），暴露出两个问题：

| 问题 | 现象 | 修法 |
|---|---|---|
| **验证器无法区分好坏** | 最优候选与"必须被拒绝"的全选探针同分 | 新增 `run_validity` 自检：最优候选必须**严格优于**最差探针，否则判定本次进化**无效** |
| **闸门永远不动** | 8 条记录全部 `insufficient` | 闸门阈值随 `verifier.deterministic` 自适应（1/1 而非 3/2） |

> **这条经历本身就是成果**：它证明"防自欺审计"不是装饰——**它在第一次运行就抓出了一个会让整个项目得出错误结论的退化解。**
> 对照 2026 年的实证：GPU kernel 优化里 73.8% 的优化出现"代理指标涨、真实指标没涨"，而且**跑得越久越严重**（10 步 26.4% → 100 步 57.8%）。

### 已验证的 Nexent 接入条件（重要，省掉踩坑时间）

| 事项 | 结论 |
|---|---|
| 不启 Docker 能否开发 | ✅ **能**。纯 SDK + mock 模型端点即可跑通 agent、工具、记忆门面、MCP |
| Python 版本 | **必须恰好 3.11**（`sdk/pyproject.toml` 上界 `<3.12` 封死）；3.12/3.13 上 pip 解析器会卡死，用 uv |
| 装哪个包 | **必须装本地 `第三方/nexent/sdk`**，不能 `pip install nexent`（PyPI 上是 Mem0 旧架构，不是同一份代码） |
| 现成环境 | 仓库根已留 `.venv-nexent311/`，可直接复用 |
| MCP 传输 | 只支持 `sse` / `streamable-http`（靠 URL 后缀判定，`/sse` 与 `/mcp`）；**stdio 不能直连**，需容器化后由 mcp-proxy 桥接 |
| MCP 单次调用超时 | **硬上限 60s**（超时会终止整个 Agent run）→ 长任务需设计 `job_submit` / `job_status` 异步模式 |
| Skill 三层机制 | L1 发现=提示注入（只有 name+description）/ L2 加载=`read_skill_md`（正文此时才进上下文）/ L3 行动=`run_skill_script`（只允许 .py/.sh） |
| Skill frontmatter | **白名单只有 5 个键**：`name`/`description`/`allowed-tools`/`tags`/`script_outputs`，其余静默丢弃 |

**行业未定不影响 P1/P2 的推进**——这正是"内核先行"的意义。
