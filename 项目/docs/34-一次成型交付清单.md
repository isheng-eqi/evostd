**三个关键工程决策**：
1. **服务层与 MCP 层分离**——服务层不依赖 MCP、不依赖 Nexent，可离线全量测试；MCP 只是薄适配。
2. **`evo_*` 分片**——`init → N×step → status → finalize`，每步秒级，**绕开 MCP 单次调用 60 秒硬超时**（超时会终止整个 Agent run）。
3. **自持存储**——判据库、锚点、台账、版本快照全部落在 `src/runs/evostd-state/`，**不落平台表**（平台 skill 表没有 version 字段，且证照字段明文入库）。

## 四、闭环实证（这是最该给评委看的一段）

`python -m evostd.smoke` 的真实输出：

```
【3】asset_blindspots：8 条资产里，**2 条违规现有判据看不见**
      · AST-2026-9000  存储位置指向已下线存储（现有判据测不到）

【4】std_propose：
    第 1 次（无任何人工确认）：裁决「rejected」
      ★ 硬锚点天生是'证伪器'不是'证实器'
    → 请人确认 2 条盲区样本
      ✓ 软确认 SA-001 / SA-002
    第 2 次（已有 2 条人工确认）：裁决「adopted」
      理由：R1/R2/R3 全部满足：可归因命中 2 条，零误报
    C 过度宽泛提案 → 裁决「rejected」
      理由：R2 未满足：在合规锚点 ['HA-001','HA-003','HA-004'] 上误报

    ★ 闭环验证：判据入库后，同一批资产的盲区 2 → 0
      —— 系统看见了以前看不见的违规，而且只花了 2 次人工确认。
```

**这一段同时证明了四件事**：
1. 系统能**自己发现盲区**
2. 硬锚点**免费证伪**，人工确认**付费证实**——两者缺一不可
3. 新判据在**它够不着的锚点**上被裁决
4. 采纳之后，**盲区真的归零**（不是靠调参，是靠长出能力）

## 五、★ 本轮被抓出来的三个真 bug（自检机制的价值实证）

| # | Bug | 后果 | 谁抓到的 |
|---|---|---|---|
| 1 | **不可编译条款被当成普通判据装进了判据库** | 它们检查的字段永远不存在 → **每条资产都判违规 → 盲区恒为 0**，整个提案链路静默失效 | 冒烟测试第一次运行 |
| 2 | **PATTERN 锚点用"查表默认值"，样例根本不匹配正则** | 3 条锚点标签与判据结论相反——**锚点本身是错的**，后面所有裁决都建在错的基础上 | **锚点自检**（`verify_anchors`） |
| 3 | `add_anchors` 去重键漏了资产内容 | 两条不同的人工确认被误判为重复 → 可归因命中少算 1 条 | 闭环计数对不上 |

**Bug 1 与 Bug 2 的性质最要紧**：它们都不会报错、不会崩，**只会让系统安静地得出错误结论**。
这正是 docs/30 不动点里那条"防自欺审计"要防的东西——
**而且它们在第一次运行就被抓到了**，不是等到答辩现场。

对 Bug 2 的修复尤其体现了纪律：**改成从正则本身生成样例，生成后当场用 `re.fullmatch` 复核；生成不出来就跳过该条款——宁可少一条锚点，绝不造一条错的锚点。**
