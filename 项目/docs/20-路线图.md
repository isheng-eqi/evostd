# 20 · 路线图：把自进化做成一个跑在 Nexent 上的闭环

> 现状（已核实）：自进化内核与两条进化线已跑通并自检通过；Nexent 平台在 WSL 里跑着（14 容器，web :3000）；
> 行业 Domain Pack **未锁定**（调研倾向：制造主 + 政务数据目录对齐样板）。

---

## 一、一句话方向

> **不做一个"接了大模型的文档问答"，而是做一个"自己会变好、并且能证明自己真的变好了"的数据资产认知智能体。**

自进化是脊椎，不是章节。三条进化线——**本体、Skill 模板、资产标识与检索策略**——各由一个**外部验证器**裁决，全程有**审计**盯着"是不是在自欺"。

---

## 二、核心架构洞察：把验证器放进 MCP 工具，让"防自欺"变成架构强制

```
              ┌──────────────────────────────────────────┐
              │   Nexent Agent（LLM）                     │
              │   角色：变异算子 + 编排者                  │
              │   ★ 它不能给自己打分                       │
              └───────────────┬──────────────────────────┘
                              │ 只能通过 MCP 工具与外界交互
        ┌─────────────────────┼─────────────────────┐
        ▼                     ▼                     ▼
┌───────────────┐   ┌───────────────┐   ┌───────────────┐
│ MCP: evo_*    │   │ MCP: data_*   │   │ MCP: kg_*     │
│ 自进化内核     │   │ 多模态数据资产 │   │ 本体与图谱     │
│ ·评估(确定性)  │   │ ·识别/理解    │   │ ·半自动构建    │
│ ·闸门裁决      │   │ ·六维资产标识  │   │ ·持续动态更新  │
│ ·存档/谱系     │   │ ·溯源引用     │   │ ·标准对齐校验  │
│ ·审计/探针     │   │               │   │               │
└───────────────┘   └───────────────┘   └───────────────┘
        ▲
        └── Skills：工作流模板（检索-推理双驱动 / 决策链路溯源 / 进化编排）
```

**关键**：评分、闸门裁决、存档决策**全部在 MCP 工具内部完成**，agent 只能"请求"而不能"修改"。
于是"模型不给自己打分"这条纪律，**在平台边界上被强制执行**，而不是靠提示词约束。

> 这句话可以直接写进答辩：**我们的防自欺不是承诺，是架构——分数产生在 agent 的手伸不到的地方。**

## 三、三阶段路线

### P1（现在做）：把内核挂上 Nexent —— 自进化成为平台能力

| 步 | 做什么 | 可验证产出 |
|---|---|---|
| 1 | 写 `evo` MCP Server（FastMCP），暴露：`evo_init` / `evo_step` / `evo_status` / `evo_finalize` / `evo_audit` | 起服务后 `list_tools` 能看到 5 个工具 |
| 2 | 注册进 Nexent（**URL 必须写 `host.docker.internal`**，不是 127.0.0.1；只支持 `sse`/`streamable-http`） | 平台 MCP 空间里能看到并健康检查通过 |
| 3 | 写 Skill 包（SKILL.md + scripts/，frontmatter **只用 5 个白名单键**） | 上传后 agent 的 system prompt 里出现该技能 |
| 4 | agent 真的跑一次进化：提候选 → 调 `evo_step` 拿分 → 闸门裁决 → 存档 | 调用序列日志 + 一条代际曲线 |

**★ 必须绕开的一个平台限制**：MCP **单次调用硬超时 60s**，超时会终止整个 Agent run。
所以进化回路必须**分片**：`evo_init`（建回路）→ N 次 `evo_step`（每次跑一代）→ `evo_status`（看曲线）→ `evo_finalize`（出报告）。**这个设计本身就是"深度理解 MCP 协议"的证据。**

吃分：**25% MCP/Skill 深度集成** + 要求⑤。

### P2：插 Domain Pack（需要定行业）

| 步 | 做什么 | 可验证产出 |
|---|---|---|
| 1 | 语料入库：文本 / 表格 / 图文三模态 | 三模态都进得来、都有资产标识 |
| 2 | 从语料抽条款与术语 → 本体 v0.1 | 本体文件（OWL/TTL）+ 覆盖率报告 |
| 3 | 标准 → **机器可校验约束**（SHACL 式：字段/基数、受控词表、跨文档合理性，每条带 `dct:source` 指回条款） | 喂违规数据 → 被拒，并报出"违反 XXX 第 N 条" |
| 4 | 用**真实语料**跑通三条进化线 | 三条代际曲线 + 审计报告 |

**这里的关键是"对齐要有牙齿"**：不是列一张"我们参考了 XX 标准"的表，而是**违反标准的资产真的进不来**。

吃分：**25% 业务价值** + **25% 算法创新性**。

### P3：初赛交付

| 交付物 | 内容 |
|---|---|
| 开发设计文档（Word） | 项目概述 / 整体方案设计 / 知识图谱构建方案 / 智能体构建方案 / 原始数据说明 / 数据处理说明 |
| Agent 完整细节 | 模型信息、工具信息、知识库信息、**调用关系图**、调试迭代经验、示例问答截图 |
| 附件 | 需要同步提交的 JSON、知识库文件说明、MCP 文件说明 |
| ★ 差异化证据 | 三条代际曲线 + 审计报告 + **"第一次运行就被审计抓出退化解"的案例** |

## 四、风险与对策

| 风险 | 对策 |
|---|---|
| Domain Pack 迟迟不定 → P2 卡住 | P1 完全不依赖行业，先做完；同时把 Domain Pack 接口固化，行业一插即用 |
| 真实语料上跑不出上升曲线 | 先用合成/半合成数据验证回路（**已完成**），再上真语料；若真语料不涨，**如实报告不涨**，并给出原因分析——这比假曲线值钱 |
| MCP 60s 超时 | 回路分片（`init/step/status/finalize`），单步控制在秒级 |
| 平台依赖白名单限制（图数据库不可用） | 图谱自研：轻量三元组 + 自研本体层，通过 MCP 挂载，不申请新依赖 |
| 评委质疑"自进化是不是噱头" | 用**可复现的证据**回答：曲线、保留集落差、对抗探针通过率、闸门裁决记录，全部可当场重跑 |

## 五、我需要你决定的只有一件事

**行业。** 其余我都能自己推进。

- 不定也能做：P1 与 P3 的骨架、Domain Pack 接口、第三条进化线、LLM 变异算子接入。
- 定了立刻做：P2 的语料与标准部分。

调研的建议是 **制造（主）+ 政务数据目录（对齐样板）**，硬理由：
- 医疗公开样例（MIMIC-IV Demo）官网原文写明 *"excludes free-text clinical notes"*，恰好砍掉多模态最出彩的长文本；真实数据需 credentialed 授权，赛期内拿不到。
- 金融会有"**国内标准 + 美国样例**"的错位（公开样例是 SEC EDGAR/XBRL，而国内标准无配套公开样例），评委一问就露。
- 制造三模态齐备、标准天然分层（ISA-95 / OPC UA / GB/T）、无隐私合规风险。
