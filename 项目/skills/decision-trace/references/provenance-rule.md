# 无源断言禁令与可采信强度评级

## 一、禁令

> **没有 provenance 的断言不允许进入推理。**

在图上用属性存在性约束实现；在本技能里用「评级」实现：缺来源的跳不会让结论直接失败，
但会**把评级压下去**，直到「不成立」。

禁令要解决的是这类失败模式：

| 失败模式 | 表现 | 后果 |
|---|---|---|
| 补全 | 「这里没记录，但按常理应该是抽取值」 | 结论看似完整，实际凭空多了一环 |
| 顶替 | 用「相似文档」当来源 | 来源与链路无关，等于没有来源 |
| 合并 | 三个来源只写一个 | 无法复核，也掩盖了来源之间的分歧 |
| 沉默 | 不报缺口 | 用户以为链路完整，做出错误决策 |

四条里**沉默最危险**，因为它不可见。所以本技能把缺口清单放在报告正文，而不是附录。

## 二、什么算「来源」

一个来源必须是下面之一：

1. **链路实际经过的节点**：`edges[].source` 指向的文档 / 记录 / 工具返回标识。
2. **实际返回的引用项**：检索返回里的 `doc` + `locator`（页码、单元格、图片区域、字符偏移）。
3. **判据库快照**：条款判定的依据是 `clause_id` + `source` + `snapshot_id`。

不算来源的：

- 「常识」「经验」「一般情况」；
- 同一份文档的另一个文件名；
- 相似度高的其它文档；
- 你自己写的解释性文字。

## 三、评级怎么算（全部由脚本计算）

设：
- `H` = 链路的跳数（`edges` 条数）
- `S` = 带非空 `source` 的跳数
- `C` = 带 `cite_index` 的跳数

| 条件 | 评级 |
|---|---|
| `H == 0` | **不成立** —— 没有链路，谈不上证据 |
| `S < H` | **弱** —— 存在无源断言 |
| `S == H` 且 `C < H` | **中** —— 可溯源，但未接到平台引用链路 |
| `S == H` 且 `C == H` | **强** —— 每一跳都有来源且可回指平台引用 |

**降级规则**：若结论声明的 `clause_id` 在判据库里找不到对应条款，评级**降一级**
（强→中→弱→不成立）。因为终点的依据不存在，整条链就没有落点。

## 四、缺口清单要写什么

对每一跳缺来源/缺引用的情况，写出三件事：

1. **缺口位置**：`from → op → to`
2. **缺什么**：`source` 还是 `cite_index`
3. **补它的动作**：例如「该跳来自解析器，需要解析器输出 provenance 四元组」
   或「该引用项在检索中未返回，需要放宽检索或改用文档级引用」

不要写「建议补充来源」这种没有动作的话。

## 五、provenance 的最小集（工程口径）

给每一条三元组/字段挂 provenance 四元组：

```
(subject, predicate, object, source)
source = doc_id + page + bbox/cell + span_offset + extractor_version + timestamp
```

- `doc_id` 与 `page`：定位到文档与页
- `bbox` / `cell` / `span_offset`：定位到页内具体位置
- `extractor_version`：同一份文档被两版抽取器处理过时，能区分
- `timestamp`：能判断这条断言是什么时候产生的

缺 `extractor_version` 与 `timestamp` 时，链路上出现「同一份文档给出两个不同结果」将无法解释。

## 六、回答模板

```
结论：<一句话>
评级：<强/中/弱/不成立>　依据：有源跳 S/H，cite_index 覆盖 C/H
链路：
  1. <from> --<op>--> <to>　来源：<source>　cite_index: <n>
  2. ...
终点依据：《<标准名>》<clause_id>　原文：「<原文>」
缺口：
  - <from> --<op>--> <to>　缺 source　补法：<具体动作>
可采信性：<能采信 / 需补来源后采信 / 目前不可采信>
```
